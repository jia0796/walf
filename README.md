# 月蝕・狼人殺主持 App

本專案方向為「狼人殺真人法官主持 App」。

App 不取代真人法官發言，而是提供：
- 主持字幕
- 上一步／下一步流程
- 角色與座位標記
- 夜間操作紀錄
- 警長流程
- 發言計時器
- 死亡、角色技能與勝負流程輔助

目前優先完成 12 人局主持流程。

---

## 主持流程核心原則

1. 法官台詞以既有定稿內容為準，不自行改寫或補字。
2. 需要法官完成操作的頁面，在必要條件尚未完成時，按「下一步」不得前進。
3. 固定提供「上一步」以修正尚可回復的誤操作。
4. 第一晚認角色只做一次；第二晚起 App 已記錄角色。
5. 魔術師必須選滿兩名對象，或選擇「不交換」。
6. 狼人必須選擇狼刀目標，或選擇「空刀」。
7. 獵人／黑狼王符合資格時，可點選一名存活玩家，或選擇「不發動技能」。
8. 女巫同一晚不可同時使用解藥與毒藥，但固定主持台詞仍須完整走完。
9. 女巫解藥台詞固定為：**「今晚他死了，你要使用解藥嗎？」**，不可自行補報座位號碼。

## 遺言判定規則（最新定稿）

遺言資格依下列規則判定，**第一天特例優先於其他一般規則**：

1. **第一天：不管怎樣死亡，都有遺言。**
   - 被狼人刀死：有遺言。
   - 被女巫毒死：有遺言。
   - 被獵人／黑狼王角色技能帶走：有遺言。
   - 其他死亡原因：同樣有遺言。

2. **白天被放逐：皆有遺言。**
   - 第二天起仍適用。
   - 不因角色不同而取消遺言資格。

3. **第二天起，夜晚死亡：隔天起來皆沒有遺言。**
   - 被狼人刀死：沒有遺言。
   - 被女巫毒死：沒有遺言。
   - 其他夜間死亡：沒有遺言。

4. **第二天起，被獵人／黑狼王角色技能帶走：沒有遺言。**
   - 即使技能是在白天死亡處理階段發動，被帶走的玩家仍沒有遺言。
   - 但被帶走玩家若本身有合法角色技能，仍須另外判斷是否能發動；「沒有遺言」不等於略過死亡事件。

5. **沒有遺言的死亡仍必須顯示淘汰字幕。**
   - 例如：**「X號玩家淘汰，沒有遺言。」**
   - 顯示完畢後，才繼續處理該玩家可能的角色技能、死亡連鎖、勝負判定與後續主持流程。

## 警長死亡後的警徽落處

主持字幕簡化為：

> **請警長移交警徽**

不需要報警長座位號碼。

警長死亡後若同時存在角色技能／死亡連鎖，採用 **B 流程**：

1. 先處理該次死亡應有的遺言。
2. 處理死亡玩家自己的角色技能。
3. 若技能造成新的死亡，繼續把**整條死亡／角色技能連鎖全部處理完成**。
4. 每次新死亡仍依遊戲規則檢查是否已達勝負條件。
5. 整條技能連鎖處理完成、且遊戲尚未結束後，才回頭處理原警長的警徽落處。
6. 顯示：**「請警長移交警徽」**。
7. 警徽移交目標必須是當下仍存活的合法玩家；另提供撕警徽／不移交的對應操作（具體按鍵文字後續再定稿）。

## 無警徽時的白天發言順序

當本局**沒有警徽**（例如警長撕警徽）時，白天發言順序不再由警長決定，改由系統直接安排。

所有需要「隨機抽籤」決定發言起點／方向的情境，UI 都要使用與警長競選抽籤一致的動畫表現：
- 按下抽籤後先播放抽籤動畫。
- 動畫期間不得提前顯示最終結果。
- 動畫結束後再公布抽中的起始玩家與順／逆時針。
- 抽籤結果一旦公布即作為本輪正式結果；若要更正，應透過既有「上一步」流程處理。

### 單一死者

若上一個夜晚只有一名死者：

1. 以該名死者的座位作為基準。
2. 系統在死者**左邊**與**右邊**兩個方向中隨機選一個方向。
3. 從該方向上最接近死者的**存活玩家**開始發言。
4. 後續發言順序依選定方向繼續排列，並略過已死亡玩家。

### 兩名死者

若上一個夜晚有兩名死者：

1. 系統先從兩名死者中**隨機挑選一名**作為基準死者。
2. 再於該名死者的**左邊／右邊**中隨機選擇一個方向。
3. 從該方向上最接近基準死者的**存活玩家**開始發言。
4. 後續依該方向排列，略過已死亡玩家。

### 平安夜（沒有死者）

若本局沒有警徽，且上一晚為**平安夜（沒有死者）**：

1. 由系統進行隨機抽籤。
2. 抽籤邏輯與「警長競選發言順序抽籤」一致。
3. 系統從目前存活玩家中隨機抽出一名起始玩家。
4. 系統同時隨機決定**順時針／逆時針**。
5. 從抽中的玩家開始，依抽中的方向安排發言順序，並略過已死亡玩家。

## 待檢查 Bug：第二天夜晚刀中獵人，獵人白天帶走平民後缺少淘汰字幕

### 實際操作情境

1. **第二天夜晚**，狼人刀中獵人。
2. 到了白天，獵人進入死亡／技能處理。
3. 獵人啟動角色技能，帶走一名平民。
4. 該平民依規則沒有遺言。

### 目前錯誤

獵人帶走平民後，流程沒有顯示：

> **X號玩家淘汰，沒有遺言。**

而是直接跳到：

> **警長決定警左警右**

也就是說，被獵人帶走的平民雖然已經被記錄為死亡，但對應的「淘汰、沒有遺言」主持字幕被整段略過。

### 預期行為

獵人白天啟動技能帶走平民後，必須先顯示：

> **X號玩家淘汰，沒有遺言。**

法官完成這段主持後，再繼續檢查：

- 被帶走的玩家是否有合法角色技能可以發動。
- 是否形成新的死亡／技能連鎖。
- 是否已達勝負條件。
- 若死亡連鎖全部完成，才進入後續流程，例如「警長決定警左警右」。

### 待程式檢查方向

請檢查「夜間死亡的獵人 → 白天發動技能 → 技能目標死亡」這條 death queue / death resolution 流程。

特別確認：

- 獵人雖然是在**第二天夜晚被刀**，但他的技能是在**白天死亡處理階段**發動。
- 技能帶走的平民必須建立獨立死亡事件。
- 即使 `hasLastWords === false`，也不能直接 advance 到「警長決定警左警右」。
- 應先建立並顯示「X號玩家淘汰，沒有遺言。」這個主持步驟。
- 完成該死亡事件及可能的後續角色技能／勝負檢查後，才能離開死亡處理佇列。

## Codex 接管注意事項

Codex 修改程式時：

1. 先以本 README 的「修改紀錄／待修正」作為目前最新規格。
2. 不自行更改法官主持台詞。
3. UI 提示文字與法官字幕要分開處理，不能把開發註解／規則提示加入主持字幕。
4. 任何必要選擇都需支援取消／更正，並確認「上一步」能恢復合理狀態。
5. 修改死亡流程時，優先確保每一個死亡事件都會被處理一次，不能因「沒有遺言」而完全沒有出局提示。
