## 共通視覺與工程約束

1. 使用專案既有**同一張共用背景**，以柔和深紫藍遮罩／漸層與古金點綴調整前景對比；頁面以暗色半透明玻璃卡、克制邊線與微弱陰影呈現。不能生成、替換或扭曲現有正式人物插畫；不可更動 SVG 圖案、顯示意義或觸發規則。
2. 不阻止雙指縮放，保留安全區、鍵盤焦點、足夠的對比度、至少 44px 有效觸控目標；支援 `prefers-reduced-motion`。動態僅做視覺回饋，不牽動真實操作判斷。
3. 所有長職業名、完整技能介紹、字幕、正式復盤事件可換行／正常捲動，不以省略、截斷、造假文字換取整齊排版。10 人、12 人、特殊角色及所有板子都要正確渲染。
4. 不增加未經同意的新遊戲流程或儲存狀態，不將 UI 改動延伸至 `engine.js`、`night.js`、`takeover.js`、`fragrance.js`、`timer.js` 之計算及遷移。
5. 只展示已有資料：沒有紀錄票型就不出復盤票型，不自行推測死亡原因，不重新推導陣營與勝負。保留 v22 及既有舊存檔向下相容、全部回退歷史。

## 第一頁：首頁（UI-01～UI-05）

- **UI-01 A｜原始結構精修**：保留「月下議會」、副標「狼人殺主持工具」、`開始主持`／`角色圖鑑`，底部 `問題回報`；只改排版，不改入口。
- **UI-02 A｜優雅暗紫藍古金玻璃**：按鈕與內容採半透明玻璃、柔和暗色層次、古金細線及可讀白字；沿用共用背景。
- **UI-03 A｜輕觸感與短轉場**：按下約 2px 輕微位移／細框變化，約 150～200ms 前景轉場；防重複點擊；焦點可辨識，減少動態效果時停用裝飾動畫。
- **UI-04 A｜自適應柔和遮罩**：背景圖片固定且不替換，用漸層改善文字可讀性；小螢幕、短螢幕、安全區及縮放不阻擋操作。
- **UI-05 A｜底部低調問題回報**：保留既有 Google Form 連結，置底、中央、可點擊範圍至少 44px；不得無提示自動夾帶使用者／對局資料。

## 第二頁：玩家人數（UI-06～UI-08）

- **UI-06 A｜垂直 10／12 人大卡**：分別呈現 10 人、12 人與既有對應板子資訊，不硬編板子數量。
- **UI-07 A｜即點即進與返回**：按壓回饋後進入相應板子清單；保留返回首頁及遊戲既有狀態。
- **UI-08 A｜彈性字級與卡片比例**：標題約 30–36px、輔助 14–16px、主數字 32–40px、卡片約 76–88px 高、間距 14–18px；依實際可視高度／320px 寬度／縮放合理調整，不固定裁切。

## 第三頁：板子選擇（UI-09～UI-11）

- **UI-09 A｜單欄橫式玻璃卡**：完整板子名稱、方向箭頭，可換行；資料動態讀取。
- **UI-10 A｜一般／特殊分段選擇**：一體式古金選中分段切換，分類變更後清單從頂端開始；不改板子所屬分類。
- **UI-11 A｜獨立捲動板子列表**：頂部標題與分類、底部上一步保留可達；長板子名稱不省略，清單獨立捲動。

## 第四頁：角色配置（UI-12～UI-15）

- **UI-12 A｜狼人／好人左右兩欄**：角色表採玻璃分區與陣營色，實際數量及名稱完全依當局；好人排序神職在前、平民在後。
- **UI-13 B｜特殊房規分組摺疊**：分為 `一般設定` 與 `板子專屬設定`，保留現有控制項、原預設、選取及提交方式。
- **UI-14 B｜夜間順序摺疊與條件分頁**：只有首夜與次夜起資料不同時呈現 `第一晚`／`第二晚起`，不變更任何夜間次序或字幕。
- **UI-15 A｜固定雙按鈕底欄**：上一步／開始主持並排；中間內容獨立捲動，避開安全區與遮擋。

## 第五頁：主持主畫面（UI-16～UI-21）

- **UI-16 A｜保留原版拓撲**：頂欄（階段／日期／板子／房規／圖鑑）、主字幕＋法官區、左右對稱各六席座位、上層工具列與下層導覽列，不重新排列座位。
- **UI-17 A｜精緻玻璃座位卡**：清楚座號／職業、古金選中線、保留警長／死亡／特殊狀態及既有多 SVG 標記，不改標記位置／意義或可選資格。
- **UI-18 A｜字幕優先分層**：主字幕最醒目；提示、手勢、選取結果在不同層次；法官內容可獨立捲動，既有階段有效按鈕與法官說明不刪改。
- **UI-19 A｜上下兩層固定底欄**：上層發言計時器、可用時的騎士決鬥、狼人自爆及重置，下層上一步／下一步；依可視寬度適度換行但不覆蓋座位，原有可用／停用條件不變。
- **UI-20 A｜平衡自適應頂欄**：階段／日期優先、板名第二，房規／圖鑑永遠可達；板名長時自然換行，不以省略形式掩蓋。
- **UI-21 A｜情境區別回饋**：選取時的提示、真正確認後的正式事件／SVG、儲存失敗的持續警示彼此分離；成功保存保持安靜，不假報成功，不改上一步／下一步／存檔流程。

## 第六頁：角色圖鑑（UI-22～UI-25）

- **UI-22 C｜三欄精簡插畫卡**：每列三張，正式角色圖片等比例（既有 5:7）、完整顯示不裁切，完整職業名置於下方、可換行、全卡可觸控；320px 寬仍以三欄為定案目標，需真機驗收可用性。首頁進入顯示完整圖鑑，主持進入僅顯示該板子角色，不增減原始範圍。
- **UI-23 A｜一體式狼人／好人分類切換**：古金選中／暗藍未選、分類保持在頂部、卡片清單獨立捲動；變更分類捲到新清單頂部。
- **UI-24 A｜沉浸式正反面玻璃卡**：正面正式插畫完整顯示、背面完整現有職業名稱／技能／目標；柔和 3D 翻轉及 reduced-motion 備援。背面長文獨立捲動，不裁切內容，避免捲動觸發翻面；保留原本翻面、`aria-hidden`／`inert`。
- **UI-25 C｜極簡遮罩關閉**：不新增醒目的 × 關閉鈕，沿用點擊卡外遮罩與既有返回提示／鍵盤關閉。關閉詳情返回原分類、原捲動位置及原角色卡焦點；離開圖鑑按原來源返回首頁／主持，不新增跨頁持久化 scroll 資料。

## 第七頁：遊戲結束與復盤（UI-26～UI-29）

- **UI-26 B｜回合時間軸**：遊戲結束與正式勝利陣營／原因置頂；完整復盤依夜／日原始事件順序在左側窄軌道／右側內容呈現；後接最終身分回顧及操作，不重新判勝。
- **UI-27 A｜逐事件玻璃卡**：同一回合多個事件各有獨立卡片，不刪／合併紀錄；正式人物插畫直接融入整張卡片背景，無獨立小圖框；完整顯示真實角色／座號／技能 SVG／效果／死亡原因／多事件。技能影響不等於死亡原因；同批出局不漏人；未記錄票型絕不補造；不自行重算事件。
- **UI-28 A｜單一摺疊面板＋三欄身分卡**：預設收合，展開一次顯示全部正式玩家；狼人／好人分組，好人神職在前平民在後。每列三張角色卡使用正式插畫、座號、身分、存活／出局及感染／轉化／原職等現有資料；收合不重算資料，不影響時間軸。
- **UI-29 A｜固定雙按鈕玻璃底欄**：`重新一局` 古金主按鈕及 `回首頁` 灰藍次按鈕並排、等寬、固定底部；復盤／身分可完整捲動到底，不被底欄遮住。沿用既有確認視窗與資料清除語意：重新一局保留板子及房規、刪除前局紀錄；回首頁清除本局紀錄；不取消確認、不調整存檔。

## 第八頁：發言計時器（UI-30～UI-33）

- **UI-30 A｜雙模式中央聚焦玻璃計時器**：設定模式中央雙滾輪，倒數模式中央大數字／圓形進度環；共同標題、關閉入口、主按鈕區層級一致。
- **UI-31 A｜中央精緻雙滾輪**：分鐘／秒數各自垂直滾動與中央吸附，上下相鄰值降亮；左右 `−10秒`／`＋10秒`；下方等寬 `開始`／`重置`，底部較小但足夠觸控的 `重設`。選定數字約 28–34px、相鄰 18–22px，既有預設 01:00、上下限、進退位不變。
- **UI-32 A｜中央圓環＋大型倒數數字**：數字約 42–58px，SVG 圓環約 180–240px（依視窗調整）；倒數中、已暫停／繼續、時間到以文字加原有色彩提示；`暫停／繼續` 與 `重置` 並排，`重設` 次要置下；沿用原警示門檻，不新增音效／震動／自動下一步。
- **UI-33 A｜柔和雙向轉場與穩定彈窗**：設定↔倒數淡入淡出／輕微縮放約 200–300ms、減少動態效果可直接切換；避免舊畫面殘影、雙重可點擊內容和遮罩殘留。重置仍恢復當次設定時間（例 01:30），重設仍恢復預設 01:00；彈窗 × 沿用原有關閉行為，不擅自暫停、歸零或加入確認視窗。

## 執行優先順序與驗收（均尚未執行）

建議分批 UI 實作及各批回歸：首頁／選人／選板 → 配置 → 主持畫面 → 圖鑑 → 結束復盤 → 計時器 → 全裝置回歸。

1. **零規則回歸**：所有板子及新接刀流程、字幕、夜間順序、技能 SVG、原先狼刀／女巫／守衛、白天警長／PK／票型、勝負／復盤因果均不改；所有既有單元／整合／UI 測試實跑。
2. **資料正確性**：v1–v22 舊存檔、當前 v22、刷新恢復、完整上一步歷史、長局保存；不新增 migration 或改動格式，沒有歷史的舊存檔不補造。
3. **導覽**：首頁／主持進圖鑑的範圍與返回、詳情翻面與遮罩關閉、復盤底欄重新一局與回首頁的原確認動作。
4. **計時器**：設定 01:30→開始→暫停→繼續→重置回 01:30；重設回 01:00；時間到 00:00，連點不重複計時，關閉重開及背景切換維持原有狀態。
5. **視覺及觸控**：320×568、一般直／橫向、字體放大、雙指縮放、長名稱、夜間法官長字幕、長復盤、多 SVG 與防遮擋。
6. **必須真機核驗**：iPhone Safari、iOS 安裝 PWA、Android、低階裝置；尤其動態工具列、安全區、慣性捲動、背景切換、存檔成本。桌面 viewport 模擬不得冒充真機通過。
7. **PWA 與素材**：仍採既有分階段快取／背景下載，不能擅自全部預快取／跳提示／更換圖片／SVG；首次載入、離線及多圖性能測量。
8. **效能與安全**：長局、多局保存與 localStorage 空間風險維持，不為省資源刪回退；多分頁依原單一主持分頁原則，不自行建立同步規則。
