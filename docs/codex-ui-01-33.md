## 分批實作

1. **UI-01～11：** 首頁、10／12 人、板子列表。精緻深紫藍／古金玻璃，固定共用背景、原入口；板子一般／特殊分段切換，清單獨立捲動。
2. **UI-12～15：** 狼人／好人角色雙欄；房規依一般／專屬的摺疊組；首夜／次夜順序條件分頁；配置底欄。所有選項原值與板子資料完全保留。
3. **UI-16～21：** 保留主畫面 2×6 左右座位、原字幕／法官／工具雙層底欄；選取與結果／SVG 分離、存檔失敗保留；不改遊戲操作流程。
4. **UI-22～25：** 圖鑑三欄角色卡（**C**）、一體式狼人／好人切換、正反面玻璃翻面、**C 極簡遮罩關閉而非新增 ×**；源自主持只顯示本板角色，關閉詳情後恢復分類、捲動與焦點。正式圖片與技能原文不變。
5. **UI-26～29：** **B 回合時間軸**（夜／日左窄軌道）、逐事件玻璃卡、人物直接融入背景而非獨立小框；最終身分一體可收合／三欄，狼人與好人分組、神職在前；重新一局／回首頁固定雙按鈕和既有確認視窗。
6. **UI-30～33：** 設定／倒數雙模式；設定雙滾輪左右 ±10 秒，下方開始／重置與小型重設；倒數大數字＋SVG 圓環、暫停／繼續、時間到；約 200–300ms 柔和雙向轉場，reduced-motion，短螢幕可達性。當次 01:30 重置回 01:30，重設回預設 01:00。

每批僅修改必要的 UI 檔案，作為可審核 commit；不要同批重構規則、復盤演算法、存檔或 Service Worker。任何既有功能與視覺要求衝突時，先保留功能及正式資料，再用 UI 層處理；將無法安全滿足的項目列為未完成，不自行改規則。

1. 跑 `npm test`；依 package scripts 與環境跑既有 UI 回歸，必要時增補針對性 UI 測試，保留測試輸出。

3. 圖鑑首頁／主持來源與返回、三欄與分類、正反翻面、長文字獨立捲動／關閉原位置；復盤完整事件、原畫、技能 SVG、票型有無紀錄及正確的死亡因果；最終身分正確含轉化者／感染者等。
